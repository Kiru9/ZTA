에이전트 생성

한국어원문 기준 2026-10-11

에이전트는 Snowflake CoWork에서 사용자를 대신해 작동하는 지능형 개체입니다. 특정 도구와 오케스트레이션 로직으로 구성되며, 데이터를 기반으로 질문에 답하고 작업을 수행합니다.

  1. Snowsight에서 AI & ML > Agent Studio로 이동합니다.

  2. 오른쪽 위의 Create agent를 클릭합니다.

    • Database and schema: DASH_DB_SI.Retail
    • Agent object name: MarketingAgent
  3. 에이전트를 생성합니다.

Instructions 추가#

Configuration 탭의 General에서 다음과 같이 설정합니다.

  • Description
    Description
    나는 마케팅 및 영업 인텔리전스 전문 어시스턴트입니다. 정형 마케팅 지표(지출, 클릭 수, 전환 수)와 비정형 고객 피드백(고객 지원 대화 기록)을 분석해 정확한 데이터 기반 인사이트를 제공하는 것이 주요 역할입니다. ‘무슨 일이 일어났는지’(수치)와 ‘왜 일어났는지’(고객 감성)를 연결합니다. 항상 전문적이고 분석적인 어조를 유지하고, 고객 지원 대화 기록에서 가져온 정보에는 명확한 출처를 제시합니다.
    영문 원문 보기
    코드 / 텍스트
    Description: I am a specialized Marketing & Sales Intelligence Assistant. My  primary role is to provide accurate, data-driven insights by analyzing structured marketing metrics (spend, clicks, conversions) and unstructured customer feedback (support transcripts). I bridge the gap between 'what happened' (the numbers) and 'why it happened' (customer sentiment). Always maintain a professional, analytical tone and provide clear citations for information retrieved from support transcripts.
  • Example question
    Example question
    클릭 수 기준 상위 5개 캠페인을 알려줘.

Tools 추가#

도구는 에이전트가 작업을 수행할 때 사용할 수 있는 기능입니다. 에이전트의 기술 목록이라고 생각하면 됩니다. 아래 각 유형의 도구를 하나 이상 추가할 수 있습니다.

Configuration 탭의 Tools 에서 다음 도구들을 추가합니다.

Code Execution tool

    활성화되어 있는지 확인합니다.

    Artifact repository 항목에 SNOWFLAKE.SNOWPARK.PYPI_SHARED_REPOSITORY 선택

Query structured data

  1. + Add semantic view를 클릭합니다.
  2. 다음과 같이 설정합니다.

  • Database & schema: DASH_DB_SI.Retail

  • Semantic view: SEMANTIC_VIEW

  • Name: semantic_view

  • Description:

    Description
    DASH_DB_SI.RETAIL의 테이블 6개를 연결하는 소매 분석용 Semantic View입니다.
- ENRICHED_MARKETING_INTELLIGENCE: 캠페인 성과 + 감성(CAMPAIGN_NAME, PRODUCT_NAME, CLICKS, AVG_SENTIMENT)
- MARKETING_CAMPAIGN_METRICS: 카테고리/날짜별 캠페인 KPI(CAMPAIGN_NAME, CATEGORY, CLICKS, IMPRESSIONS, DATE)
- PRODUCTS: 제품 카탈로그(PRODUCT_ID, PRODUCT_NAME, CATEGORY)
- SALES: 지역별 판매 거래(PRODUCT_ID, REGION, UNITS_SOLD, SALES_AMOUNT, DATE)
- SOCIAL_MEDIA: 플랫폼/카테고리별 인플루언서 언급(CATEGORY, INFLUENCER, MENTIONS, PLATFORM, DATE)
- SUPPORT_CASES: 고객 지원 상호작용(ID, PRODUCT, TITLE, TRANSCRIPT, DATE)
주요 조인: ENRICHED_MARKETING_INTELLIGENCE.PRODUCT_NAME → MARKETING_CAMPAIGN_METRICS.CATEGORY; PRODUCTS.PRODUCT_ID → SALES.PRODUCT_ID. 마케팅 노출 → 판매 성과 → 판매 후 고객 지원까지 전체 흐름을 분석할 수 있습니다.
    영문 원문 보기
    코드 / 텍스트
    Retail analytics semantic view in DASH_DB_SI.RETAIL connecting 6 tables:
- ENRICHED_MARKETING_INTELLIGENCE: Campaign performance + sentiment (CAMPAIGN_NAME, PRODUCT_NAME, CLICKS, AVG_SENTIMENT)
- MARKETING_CAMPAIGN_METRICS: Campaign KPIs by category/date (CAMPAIGN_NAME, CATEGORY, CLICKS, IMPRESSIONS, DATE)
- PRODUCTS: Product catalog (PRODUCT_ID, PRODUCT_NAME, CATEGORY)
- SALES: Sales transactions by region (PRODUCT_ID, REGION, UNITS_SOLD, SALES_AMOUNT, DATE)
- SOCIAL_MEDIA: Influencer mentions by platform/category (CATEGORY, INFLUENCER, MENTIONS, PLATFORM, DATE)
- SUPPORT_CASES: Customer support interactions (ID, PRODUCT, TITLE, TRANSCRIPT, DATE)
Key joins: ENRICHED_MARKETING_INTELLIGENCE.PRODUCT_NAME → MARKETING_CAMPAIGN_METRICS.CATEGORY; PRODUCTS.PRODUCT_ID → SALES.PRODUCT_ID. Enables end-to-end     analysis from marketing exposure → sales performance → post-sale support.

  • Add 클릭

Search documents and unstructured data

  1. + Add search service를 클릭합니다.
  2. 다음과 같이 설정합니다.
  • Database & schema: DASH_DB_SI.Retail
  • Search Services: DASH_DB_SI.RETAIL.CAMPAIGN_SEARCH
  • Name: Search
  • Max Results: 4
  • ID Column: CAMPAIGN_NAME
  • Title Column: CLICKS

  • Add 클릭

Custom tools

  1. +Add를 클릭합니다.
  2. 다음과 같이 설정합니다.
  • Resource type: procedure
  • Database & schema: DASH_DB_SI.Retail
  • Custom tool identifier: DASH_DB_SI.RETAIL.SEND_EMAIL()
  • Name: Send_Email
  • Warehouse: Custom > DASH_WH_SI
  • Query timeout: 60

  • Paramter: body

    • Description
      Description
      HTML 문법을 사용해줘. 받은 내용이 Markdown이면 HTML로 변환해줘. body가 제공되지 않으면 마지막 질문을 요약해서 이메일 본문으로 사용해줘.
      영문 원문 보기
      코드 / 텍스트
      Description: Use HTML-Syntax for this. If the content you get is in markdown, translate it to HTML. If body is not provided, summarize the last question and use that as content for the email.

  • Paramter: recipient_email

    • Description
      Description
      이메일 주소가 제공되지 않으면 현재 사용자의 이메일 주소로 보내줘.
      영문 원문 보기
      코드 / 텍스트
      Description: If the email is not provided, send it to the current user's email address.

  • Paramter: subject

    • Description
      Description
      제목이 제공되지 않으면 "Snowflake CoWork"를 사용해줘.
      영문 원문 보기
      코드 / 텍스트
